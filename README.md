# TinnitusHelp.me

Comprehensive and user-friendly blog site aimed at providing a helpful resource for individuals dealing with tinnitus. Built with Next.js, TypeScript, and Material UI, this blogs features in-depth articles, tips, and advice to better understand and manage tinnitus. In addition to valuable information, the platform also offers therapeutic audio sounds as a unique form of relief for users. The blog site is responsive, ensuring seamless navigation on all devices. Contribute to making this initiative more beneficial.

## Getting Started

First, run the development server:

```bash
npm run dev
# or
yarn dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

You can start editing the page by modifying `pages/index.tsx`. The page auto-updates as you edit the file.

[API routes](https://nextjs.org/docs/api-routes/introduction) can be accessed on [http://localhost:3000/api/hello](http://localhost:3000/api/hello). This endpoint can be edited in `pages/api/hello.ts`.

The `pages/api` directory is mapped to `/api/*`. Files in this directory are treated as [API routes](https://nextjs.org/docs/api-routes/introduction) instead of React pages.

This project uses [`next/font`](https://nextjs.org/docs/basic-features/font-optimization) to automatically optimize and load Inter, a custom Google Font.

## Push notifications for new content

The mobile app sends a "New Post" notification when a document appears in the
matching Firestore collection (`posts`, `sounds`).
**`npm run sync-content`** is what puts it there. Run it from a checkout after a
deploy has gone live; it needs the `FIREBASE_*` credentials.

**Do not move it back into `npm run build`.** It used to live there, and because
a Vercel build finishes before the deployment is promoted, notifications went out
while the URL still returned 404 — taps in the first ~15 seconds hit a missing
page. The script now polls the real article URL and refuses to announce a page
that is not yet reachable, so it is safe to run early and safe to re-run: content
it skips stays eligible and still notifies exactly once on a later run.

Content dated more than 48 hours ago syncs silently, so backfills and imports
never notify.

### Automating it

The sync is deliberately manual — nothing fires it on deploy today. If you want
that, `public/content-index.json` (regenerated by every build from
`scripts/generateContentIndex.js`) lists every published page with its title,
date and canonical URL. Because it ships inside the deployment, anything visible
in it is served by a deployment that is already live, which makes it a safe
trigger: poll it from CI or a scheduled job and sync whatever is new. If you
replace this site with a different stack, keep serving `/content-index.json` in
the same shape and that path stays open.
